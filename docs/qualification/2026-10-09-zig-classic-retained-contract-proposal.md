## Decisions and scope

Propose three small pure modules: `retained_geometry.zig`, `retained_semantics.zig`, `retained_text.zig`, with focused tests integrated later by their authorized owner. These names are Proposed, not existing APIs. Foundation handles geometry, immutable owned semantic frames, stable focus and existing atlas measurement/clipping. It contains no authority commands, Classic action union, camera, renderer, event loop, persistence or font acquisition. Classic/editor/guide projections are subsequent slices (frozen intake, §§ Shared text/assets/semantics, Proposed bounded implementation split and qualification).

Source contracts are inherited only where cited. Additional finite-overflow rejection, explicit fallible ownership, configurable resource budgets and generation-token representation are Proposed Zig policy, not Rust parity claims.

## Geometry API

Proposed `Rect { min:[2]f32,max:[2]f32 }`, `Rect.fromXYWH(x,y,w,h) GeometryError!Rect`, `contains(point) bool`, `intersection(other) ?Rect`, `containsRect(other) bool`, `overlaps(other) bool`. Finite constructor clamps negative width/height to0, matching PlatformRect; reject nonfinite inputs and overflow in derived max as Proposed strengthening. contains is inclusive on all edges and false for nonfinite points. Intersection requires strictly positive width/height; overlaps separately requires each intersection dimension>0.01. Empty rectangles can contain their edge point but have no positive intersection (`src/ui/platform.rs:49-100`; `src/presentation/ui.rs:45-68`). No UI scale or viewport sanitization belongs in generic Rect; screen projection owns its own source-specific policy.

Literal independent examples: Rect.fromXYWH(10,20,-4,8) becomes min(10,20),max(10,28); contains(10,28)=true, contains(NaN,20)=false. Intersection([0,0]..[10,10],[10,2]..[12,8])=null. Intersection([0,0]..[10,10],[9.995,0]..[12,10]) has positive width but overlaps=false because width<0.01. These expectations follow the cited comparisons, not output from a candidate port. Extents/colors that overflow through x+width are Proposed rejection tests.

## Semantic owned-frame API and limits

Proposed distinct `NodeId` and `ActionId` UTF-8 byte identities; equality compares exact bytes. Frame-owned identifiers are deduplicated or separately copied, never pointers into mutable caller/editor state. Preserve roles, name, description, optional value, enabled/selected/focusable, hierarchy_level/expanded, optional action/bounds, visible and ordered children. Root role Application; node IDs globally unique; action IDs globally unique when present; an action-bearing node must be focusable. Disabled actions may still exist and be focusable metadata; actionability/filtering belongs to projection (`src/ui/accessibility.rs:9-40,116-223,240-287`). Do not silently normalize/case-fold IDs or descriptions.

Proposed flat depth-first node storage with parent index and a separate child-index array. Each node stores a range into that array, preserving ordered direct children even when intervening subtrees make direct node indices noncontiguous. Validate parent/child consistency, root reachability, acyclicity and child-index bounds; flat traversal avoids unbounded recursive stack use. `FrameInput` jointly borrows ordered node specifications, ordered announcements, owner specification/context, prepared base/modal focus orders and focused/restore identities only during construction. `Announcement { kind:Status|Error, code:UTF8, message:UTF8 }` retains exact source order and owns copied code/message bytes; FrameView exposes the ordered announcement slice (`src/ui/accessibility.rs:226-245`). `OwnedFrame.init(allocator,input,limits) FrameError!OwnedFrame`; `deinit(*OwnedFrame) void`; `view(*const OwnedFrame) FrameView`; `node(view,NodeId) ?NodeView`; `visibleNodes(view,clip,output) CapacityError![]const NodeIndex`. Exact flat topology representation may be resolved during implementation review without widening semantic scope.

`Limits { max_nodes,max_id_bytes,max_text_bytes,max_focus_actions,max_announcements }` is explicitly supplied by the consumer with checked byte totals/counts and no unbounded defaults. These are Proposed semantic budgets; Rust supplies no cited fixed node/text cap. No512-node cap is inferred from panel capacity. Use owned dynamic storage for semantic strings/nodes because editor names/text are not fixed ASCII buffers. Use count-sized owned slices for focus orders, not permanently huge embedded arrays. Mandatory per-consumer admission rule: before any Classic/editor/guide projection is admitted, its numeric limits must be frozen in a reviewed consumer contract, including exhaustion behavior; foundation accepts parameters but no default or guessed consumer budget. Allocation accounting counts every copied ID/name/description/value/announcement code/message/owner-context/focus and restore ID byte, node/announcement/child-index/focus-order count, checked metadata bytes and every token-reference slot, not only unique source bytes. Extend Limits with max_child_indices, max_owner_context_bytes and max_owned_bytes; checked sum/multiply rejects overflow as LimitExceeded. Announcements count even when not visible; zero max_announcements permits only an empty list. Focus indices into a shared owned ID table add metadata, not duplicate arbitrary IDs. Token object allocations and candidate storage must fit the allocator and separately declared limits; resident plus one staged candidate is the maximum frame construction population. Reject LimitExceeded before install; invalid UTF-8 rejects InvalidUtf8. Existing Rust strings already guarantee UTF-8.

Views and returned slices borrow the resident frame until its next successful replacement or deinit. They must not cross host asynchronous delivery; copied semantic events need their own owned payload plus owner identity. Proposed `FrameSlot.replace(input,limits)` stages one complete atomic unit: owned nodes/child indices, ordered announcements and all their bytes, retained owner tokens/copied context, prepared focus ID table/base/modal orders, focused and restore indices, and frame metadata. Validate topology/IDs/focus/bounds/UTF-8/counts/byte budgets, then swap the whole unit once and release the old unit. Any OOM, reference overflow, invalid input or capacity failure releases only staged allocations/token references and preserves old nodes, announcements/order/code/message, owner/context, base/modal/focused/restore state and outstanding old-view validity; success invalidates old views. FrameView includes owner/focus/announcements alongside nodes; no separate early focus or owner publication is permitted. Owner is move-only by convention, deinit exactly once. Arena allocator contexts are acquired transiently from the current arena, never cached across owner movement. Current editor inventory explains the same arena-context risk (frozen intake, § Editor retained widgets; `task-3c-editor-seams.md`, § Allocation/lifetime seam).

Culling is presentation selection, not deletion: never discard offscreen semantic nodes/text from OwnedFrame. `visibleNodes` checks source visible and positive clip intersection only for bounded nodes; unbounded nodes remain semantically available but require a later projection policy before sighted drawing. Focus order is explicitly supplied by screen projection, independent of culling. Editor focus can reveal offscreen rows, so a generic visible-only tab policy is forbidden (`src/editor.rs:325-355,685-709`).

## Focus and event-owner identity

Proposed `OwnedFocus` stores byte-owned base_order, optional modal order and restore ActionId. `init/replaceBase/replaceActive/openModal` are allocator-fallible, staged operations; `requestFocus`, `next`, `previous`, `closeModal` are nonallocating after storage preparation: all IDs reside in the prepared owned ID table, orders/focused/restore use indices, and transitions choose existing indices without copying arbitrary ID bytes. An unknown requested identity returns false; only fallible staged order preparation may introduce IDs. Stable-unique retains first occurrence and order. Initial focus is first base item. Replacing base preserves focus if it remains, else first, only when modal absent. Replacing active modal rejects empty and preserves restore target. Opening nested modal rejects ModalAlreadyOpen; empty modal rejects EmptyModal. Closing restores saved action if still in base else first. Movement wraps, empty clears focus. Source's missing-current default index0 means Next chooses second item when at least2, Previous chooses last; preserve that exact fallback rather than invent first-on-next (`src/ui/accessibility.rs:321-452`).

Literal focus vectors: base[A,B,A,C]=>[A,B,C], initial A; previous=>C; next=>A. Focus B, open[X,Y]=>X, next=>Y; replace base[A,C] while modal retains modal focus; close=>A because B disappeared. Opening empty or nested modal preserves prior state. replaceActive[Z] during modal selects Z but keeps original restore B. No widget enablement or modal geometry is synthesized by OwnedFocus.

Rust source SemanticInputOwner uses Rc identity for resident/draft, exact hold/context and optionality; equal-looking content from a replaced resident must fail identity match (`src/ui/accessibility.rs:42-87`). Proposed platform-neutral allocation-identity owner uses `TokenRef` to a live allocator-owned reference-counted token, equivalent in identity purpose to source Rc. `Owner { resident:TokenRef,hold:?u64,context:owned UTF8,draft:?TokenRef }`: resident/draft compare live token allocation identity; hold compares exact optional numeric value; context compares exact bytes. This replaces the earlier unresolved epoch proposal; no local counter or hash substitutes for identity. The full lifecycle is UI-thread-only, with no thread-safe or asynchronous cross-thread claim. `TokenRef.create(allocator)` starts refcount1 and is allocator-fallible. `retain` checks usize overflow and returns ReferenceOverflow without mutation; `release` decrements a nonzero count and destroys/frees only at zero. Copying a TokenRef value does not create ownership; every owned copy explicitly retains and releases exactly once. Token allocator is stable and recorded for final release; no arena-context pointer escapes a moved owner.

Frame candidates retain incoming resident/draft tokens before installation, unwind all retained references on any failure, and share the same identity only when deliberately supplied the same live token. Owned queued semantic-event copies retain their token(s) and own context/payload bytes; a retired frame can release its references while queued events keep the old allocation live, preventing address reuse until the final event releases it. Borrowed views never retain. No unowned raw token pointer may outlive its owning reference, and double release is a programming contract violation. Later host queues must freeze independent count/byte limits, explicitly bound enqueue, and drain/release retained event references on dispatch, rejection, cancellation and shutdown; this foundation provides no queue, scheduler or unbounded retention. Owner metadata is session-local and never persisted. `matches` compares all fields and optionality; replaced resident with identical content fails. UI-thread token overflow and allocator-OOM tests are Proposed and unexecuted (`src/ui/accessibility.rs:42-87`).

Literal identity vectors: same live resident token R/holdnull/context'guide'/draftnull matches itself; independently allocated resident token S fails, hold0 fails againstnull, context'classic' fails, present draft token D fails againstnull. Replaced resident with identical bytes still fails. These are formula expectations from source identity, not executed results.

## Text measurement, culling and UTF-8 contract

Proposed borrowed `AtlasView` exposes frozen entries/generator metadata validated from existing committed metrics; no texture decoding/upload and no new glyphs. `measure(atlas,font_size,weight,utf8) TextError!Measurement`; optional `measureBoundaries` returns scalar boundaries in caller-provided buffer with explicit capacity error. Validate font_size finite>=0 and generator font_px finite>0, reject derived scale/advance overflow, missing/mismapped entries and unsupported scalar. Sum each exact weighted advance times font_size/font_px in source scalar order with f32 arithmetic; spaces advance but emit no glyph. No shaping/kerning/newline normalization (`src/ui.rs:198-221,650-713`; `tests/ui_assets.rs:373-412`).

Source printable coverage is only U+0020..U+007E. Proposed UnsupportedCharacter includes codepoint and UTF-8 byte offset. Valid UTF-8 editor data, semantic text, preedit and original buffer remain intact on failure. Invalid UTF-8 is a separate error. Foundation never substitutes '?' or drops a scalar. A later reviewed host may display an explicit unsupported-text status or supported fallback, but this proposal selects no new font or fallback asset and claims no full Unicode render coverage (`src/ui.rs:666-689`; frozen intake, §§ Editor retained widgets, Shared text/assets/semantics).

Source batch payloads: glyph rect/uv/color are three4-f32 vectors (48 bytes), panel rect/color two4-f32 vectors (32 bytes); logical coordinates and finite RGBA are preserved. Source validates finiteness but does not clamp color lanes to0..1. Glyph cap8192 and panel cap512 are inherited render-batch caps, not semantic text limits (`src/ui.rs:32-33,421-489,610-636`). No GPU vertex binding agreement is qualified by these pure records.

Proposed pure `GlyphPlacement`/`PanelPlacement` output uses caller-owned capacity or staged owned batch bounded by those caps. Every append validates complete operation before commit; unsupported char/mapping/overflow/cap/OOM leaves prior batch unchanged, as source push_text stages glyphs before extend. Fully clipped glyphs and spaces do not consume emitted-glyph capacity, but unsupported characters still fail even when outside clip; measured advance remains unclipped (`src/ui.rs:504-554,804-838`). Source clipped glyph formula: L=max(rect.x,clip.x),T=max(...),R=min(rect.x+w,clip.x+w),B=min(...); empty if R<=L or B<=T; UV offsets and extents change by intersection fractions. Generic color/batch behavior remains separate from semantic-only frame install.

## Bounded implementation and review gates

1. Geometry plus pure rectangle/UV formula tests, no atlas acquisition.
2. Owned semantic frame validation/staged replacement and source focus automaton, with allocation-failure sweep, limits, duplicate IDs, invalid topology, modal restoration and owner identity tests. Allocation-identity UI-thread token representation is selected as Proposed; review it before code.
3. Frozen metrics reader/validation, weighted measurement and pure glyph culling, literal witnesses above plus source atomicity/cap/error vectors. Do not integrate renderer or Classic/editor projections here.

All tests are Proposed future qualification: compilation, behavioral RED/GREEN, Debug/ReleaseSafe and repo-required authorized gates remain unrun. Independent review should check storage accounting, no escaped borrows, no allocator context retained across moves, complete OOM preservation, exact f32 order and distinction between source/invented policy. Success of this foundation establishes only pure semantics/geometry/text placement, never host accessibility, native/browser IME, assets provenance approval, camera/ray picking or full game acceptance.

Gaps/decisions: independent review pending; allocation-identity UI-thread token lifecycle newly Proposed and awaiting fresh review; numeric consumer resource budgets must be frozen before each projection admission; borrowed atlas loader representation pending existing asset-plan approval; Unicode host fallback explicitly unselected. accepted3G and real renderer/host integration remain separate prerequisites.
