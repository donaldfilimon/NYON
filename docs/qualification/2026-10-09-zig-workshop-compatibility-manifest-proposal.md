## Sorted container choice and publication ownership

**Proposed:** a single private generic `SortedOwnedMap(K,V)` backed by `std.ArrayList(Entry)` with one binary-search/key-order contract for every entity map, owners and inventory. Unique resident keys; `entries()` always ascending. Fixed-ID compare uses raw bytes; string-key compare uses validated content. Lookup returns const borrow invalidated by mutation/deinit. No std hash-map iteration or per-record independent sort logic. This choice avoids inventing a BTree API; it trades O(n) insertion shifts for simple inspectable deterministic storage. Performance remains unmeasured.

`insertCopy(allocator, borrowedKey, borrowedValue)` is the sole initial public mutation primitive: reject duplicate with proposed `DuplicateKey` before allocation; clone key and value into temporaries; reserve one additional slot; after all fallible work succeeds insert with `insertAssumeCapacity`. On success map owns clones, caller still owns originals. On clone/reserve failure destroy every temporary, preserve resident entries and do not publish a new key.
