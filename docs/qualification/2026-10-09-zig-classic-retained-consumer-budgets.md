### Proposed current-source generation and recovery protocol

Caller owns checked u64 source_revision, incremented on every projection-affecting editor buffer/IME/validation/error/preference/mode/modal/guide mutation, even when resident/draft token identity is unchanged. Revision overflow rejects the mutation before applying it with typed RevisionExhausted, preserving source and frame. Frame publication records immutable `(source_revision, resident token, draft token, hold, full context)` as published_revision/owner. State is Current or Stale{failed_revision, published_revision, typed failure}. Any failure after source mutation, including limits/OOM/invalid UTF-8/token creation failure, enters Stale. Every frame-derived Activate/Focus/EditorCommit/Confirmation/GuideLocation event requires Current, equal current/published/event revisions and exact current owner/modal context; otherwise typed StaleProjection rejects without authority mutation. Same draft token alone never proves freshness. A mode/modal opening updates current intended mode/context and blocks underlay dispatch before attempting projection; failed opening remains blocked Stale, never restores interactive underlay from old pixels. Source truth and buffer mutation are still owned by accepted3E/3I.

Recovery remains concrete: a separate current-source EditorRecovery operation vocabulary DeletePreviousScalar(FieldKey), DeleteSelection(FieldKey), ReplaceSelection(FieldKey,borrowed text), CancelPreedit(FieldKey), DismissCurrentConfirmation, CloseCurrentGuide, CancelEditor follows accepted3E/3I transaction semantics. Each operation receives current revision, actual current resident/draft tokens, hold/context and typed active FieldKey; validate against current source editability/selected section/world/modal, never infer target from old-frame bounds or old focus. Delete/replace use current source cursor/selection and UTF-8 scalar boundaries; reject invalid cursor/UTF-8 through accepted transaction outcome. Input text admission remains3E's contract, not output budget. While a current confirmation exists field recovery rejects; only DismissCurrentConfirmation is allowed and preserves draft. CancelEditor with dirty draft requests the actual current CancelDirty confirmation; it does not bypass confirmation. Confirm is prohibited while Stale; dismiss can unblock editing after reprojection. Guide close removes current hold through3I; restore old focus only after matching current owner and successful publication. The host must expose typed recovery to the current actual field through its separately accepted editor input/focus seam; binding that seam and diagnostic channel is a dispatch prerequisite, not assumed implemented.

After each successful recovery mutation, retry complete projection once at the new revision. Also retry after a relevant normal current-source mutation or an explicit RetryProjection request at unchanged revision (for transient OOM or released budgets); no infinite spin or silent asynchronous promise. Failure keeps Stale and old frame unchanged. Reducing oversized text through deletion or replacement permits admission again; dismiss/guide-close/reverting via existing confirmed transactions can remove oversized/current-mode output. Clearing the display error does not delete external errors automatically; their accepted owner may explicitly acknowledge them through its existing typed current-source operation once bound. On success atomically commit full frame and associated focus/owner/occurrence state at that exact revision, then set Current and clear stale diagnostic. If source changes during build reject candidate with SourceChanged and retry only the newest requested revision; no mixed snapshots. Stale render is explicitly stale and noninteractive, no truncated view. Pending unknown host input is never discarded/coalesced by this policy.
