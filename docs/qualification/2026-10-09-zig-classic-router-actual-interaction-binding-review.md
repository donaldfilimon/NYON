### Issue 1: Contact source association is required but its concrete protocol remains deferred
- **Severity**: major
- **Section**: Exact event-to-consumer sequence, line53; Finite consumer guard and lifecycle, line72; C predecessor, line82
- **Description**: Line53 says “Implementation must bind this source association”; line72 says “implement a bounded nonowning finite scalar association or explicitly reject that path under the scoped review”; line82 defers complete source-domain association to implementation review. These name the invariant and storage restrictions without selecting the lifetime representation and transition policy. The actual controller stores only ID/source/action/coordinates/moved state (classic_interaction.zig:43–47), and its public queries expose only existence/count (61–69). Thus current capability validation plus full action equality cannot tell whether a surviving old contact belongs to the current resident/draft/context/hold domain. Conversely, comparing admission revision with every current revision would incorrectly revoke the contact after its own admitted focus/orbit publication. No per-contact cancel export exists (163–165 clears all), so even the mismatch/retirement behavior must be specified. A release over an enabled identical launch or guidance action after root replacement is the concrete ambiguity. Stale projection after admission followed by retry is another case requiring an explicit decision. This is a specification gap, not a demonstrated current product vulnerability; router pointer implementation is still pending.
- **Suggestion**: Before C dispatch, freeze and independently review a concrete bounded caller protocol. Specify scalar fields and capacity, initialization after successful begin, admission-error preservation, identity/generation comparisons that never dereference retired TokenRefs, and distinction between same-domain revision progression and genuine domain replacement. State exactly what update/end do on mismatch or Stale, when association entries retire after end/cancel/teardown, and how whole-controller cancellation or inert old contacts interacts with the accepted lifecycle. Registry root-slot index/generation scalars are a feasible candidate using existing SlotTicket values (classic_input.zig:27–48), but this review does not adopt that design or claim it solves every transition. Require replacement/address-reuse, same-action/new-domain, own-focus/orbit revision, post-admission publication failure/retry, end-null/pinch-survivor and ID-reuse fixtures. Measure ordinary storage without adding retained references or spending the four-slot headroom. A separate accepted binding before C is sufficient; A need not implement successful pointer routes.
- **Status**: open

### Verified strengths
- Actual specialization, tagged payloads and return families match classic_interaction.zig:35–42,71–90,118–165. begin checks finite position, duplicate shared ID, then capacity before mutation. update/end optional returns and pure progress despite null are accurately distinguished from Session.Result and Commands.Interaction/Dispatch. UiAction values contain no borrowed strings or TokenRefs.
- The selected pointer query uses actual producer output and a copied GeometryView rather than an invented FrameView overload. H1 public nodes, lookup and borrow expiry are real (retained_semantics.zig:536–569). Existing UI hitTest scans enabled action nodes in producer order; consumesPointer uses the exact left/right/top/bottom, tray and help formulas (classic_ui.zig hitTest/consumesPointer). The proposal preserves disabled-row skipping, marker append precedence, no extra visible-node filter and inclusive Rect.contains boundaries (retained_geometry.zig:33–40). UI.validateAction separately checks trusted publication revision/full owner and enabled capability. Root/source mode checks guard public FrameView shape; no arbitrary caller-provided view may become the coordinator's published authority.
- Geometry is copied only from successful UI publication, associated with actual current frame/owner/revision, preserved on failed publication and unavailable for guide/editor dispatch. Ending node/action/frame/Header borrows before mutation preserves H1 lifetime rules. No query Header, additional retain or allocator failure channel is introduced. Optional GeometryView and whole Coordinator layout remain honestly unmeasured.
- Independent geometric equivalence fixtures are explicitly required against separately prepared producer sources with literal boundary formulas, including narrow viewport, scale extrema, help, Settings, marker, disabled row, tray and exact edges. These are future acceptance obligations; this review did not execute them. Missing/mismatched source geometry must reject before contact/focus changes.
- Contact admission precedes Session focus changes, with checked revision before effective source change. Post-admission reprojection failure preserves admitted effects and old backing while entering Stale. Whole-vector derived overflow rejects before camera mutation while retaining actual controller progress; nonfinite release can still consume a contact and dispatch using its last finite gesture coordinate. Camera's componentwise filters are not relied on as the whole-vector guard.
- Absent-guide Open, focus loss, whole touch cancellation and teardown clear contacts; repeated guide actions do not independently cancel. Suspend resets input/clock and preserves contacts/baseline, while occlusion preserves contacts. Guide whole-advance/advisory suppression and first resumed delta0 remain intact. FIX1 source focus versus published focus, Settings nonnullable focus and real28+4 ledger remain authoritative.
- Four-path sole worker ownership at line76 explicitly supersedes old parent-owned registration prose. A/B/C remain sequential increments in the same coordinator with frozen predecessors and cumulative qualification. The executing HUD setter remains a conditional separately accepted predecessor; no interim setter implementation is adopted by this review.
