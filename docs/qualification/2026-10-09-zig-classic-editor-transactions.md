# Task 3D: detached editor transactions and authority replacement

Current source contract, inspected 2026-10-09. This is research, not implementation or a gate result. Only this report is owned by this task. The prepared the scoped Task3C requirements owns the by-value editor/modal capsule and atomic current-content replacement; 3D supplies operations and AppCore integration. Actual widget/layout admission remains 3H. The 3C implementation was not present when this research began.

## Current Rust transaction invariants

`EditorState::new` owns a detached ORIGINAL clone and current draft. Dirty means draft value inequality **or any parse error**. Saving/loading never changes ORIGINAL or active AppCore authority. A load can therefore make an editor dirty relative to the scenario from which it opened. Candidate extraction rejects InvalidText before semantic validation; warning-only candidates remain admissible (`src/editor.rs:138–183,222–238`).

| Operation | Request and confirmation contract | Result and preservation |
| --- | --- | --- |
| Load, clean | Read immediately; no modal. | Absent: `NO SAVED SCENARIO`, false. Raw load failure: Store error. Present record: decode to a temporary draft **and semantically validate**, then replace current only on success; `SCENARIO LOADED INTO DRAFT`, true. Decode/validation failure is Codec error and retains old draft. |
| Load, dirty | Open LoadDirty, return false, **do not read the store**. | Confirm reads the then-current slot; no payload was captured at request time. Dismiss performs no read/replacement. |
| Save | Reject active modal, then InvalidText, then canonical encode/semantic validation, **then** probe raw occupancy. | Raw load failure reports Store error, neither confirms nor writes. Absent saves immediately; payload opens OverwriteSave with independently captured encoded bytes. Successful save reports `SCENARIO SAVED`; it does not make the editor clean. |
| Confirm overwrite | Take and save the captured bytes. | No re-encode, no decode of old slot, no second occupancy check. A slot changed after request can be overwritten by confirmation. Failure preserves current/ORIGINAL and old durable data, but consumes the modal and captured bytes. |
| Apply | Reject active modal; validate current and capture the resulting owned ScenarioV1. | Open ApplyAndRestart. Confirm freshly validates current, then compares the **entire ScenarioV1 value** to the capture. InvalidText/Validation, missing capture, or inequality produces no application. Success returns the captured validated value to AppCore. Editor itself never installs it. |
| Revert/default/regenerate | Always require their respective confirmation, even if currently clean; requests with an active modal are inert. | Confirm replaces current, resets all text buffers/parse errors, clears captures/modal. Revert uses ORIGINAL; factory uses default seed/rules/worlds; regenerate replaces worlds from current typed seed/rules. ORIGINAL stays unchanged. |
| Cancel | Clean: immediate close. Dirty: open CancelDirty. | Confirm CancelDirty returns a close outcome; dismissal leaves current intact. **Direct request_cancel is an exception to the active-modal guard:** it can replace another modal when dirty or return immediate close when clean. UI background actions are disabled during a modal. |

Exact request/load/save/confirm implementation: `src/editor.rs:473–684`. Save validation is surfaced as `EditorError::Codec(CodecError::Validation)` through encode_draft; apply validation is `EditorError::Validation` through validate_candidate. InvalidText is distinct in both. Other precise editor errors are UnknownWidget, NoConfirmation, StaleConfirmation and ConfirmationActive (`src/editor.rs:118–135`; `src/scenario/codec.rs:12–48`).

`confirm` takes the modal **before** dispatch. Failed confirmed load/save and failed/stale apply therefore require a fresh request. Overwrite takes its bytes before calling save; apply takes its value before revalidation. Missing overwrite payload means NoConfirmation; missing apply payload means StaleConfirmation. A second confirm has NoConfirmation. Dismiss explicitly clears both captures and changes neither draft nor slot (`src/editor.rs:621–682`).

Successful draft replacement rebuilds canonical buffers and clears parse errors. It does **not** reset section, selected world, focused identity, preedit or scroll, nor clear a previous store message on revert/default/regenerate. The subsequent widget rebuild can perform layout-specific focus admission/clamping; do not invent a headless replacement focus reset in 3D (`src/editor.rs:473–553,711–717`; `src/editor/layout.rs:190–223`). Keep 3C's existing value semantics and let 3H own real widget consequences.

## Raw presence, decoded validity and errors are separate

Rust ScenarioStore returns `Result<Option<String>, StoreError>`. Occupied means **successful Some**, including an empty or invalid JSON string. It does not mean every existing filesystem object or unreadable byte sequence. Native load accepts at most 65,536 bytes and valid UTF-8; oversized data and invalid UTF-8 fail raw loading, so request_save fails rather than asks to overwrite them. Native other I/O failures also block. Primary fallback occurs only for absence; malformed readable primary, oversized primary and failed primary never consult legacy. Save targets primary only (`src/scenario/store.rs:10–35,199–259`; `tests/scenario.rs:319–350,419–474`). Browser also rejects oversized raw load, whereas Rust MemoryScenarioStore has no length check (`src/platform/web.rs:62–96`; `src/scenario/store.rs:56–66`).

Reviewed Zig RawStore has `Allocator.Error!LoadOutcome` = absent / owned payload / owned StoreFailure, and `Allocator.Error!SaveOutcome` = saved / owned StoreFailure. OutOfMemory is a resource error, not a corrupt-slot or default-data outcome. Failure retains record, kind, optional cause/message, maximum size and secondary cleanup error. Payload/message ownership uses the operation allocator; deinit or transfer exactly once (`zig/src/classic_store.zig:35–115`). A 3D scenario facade must reject `!raw.matchesRecord(.scenario)` **before any callback**: RawStore's generic load/save only verifies its own advertised record, so a valid preferences facade is otherwise callable.

| Actual adapter result | Load transaction | Save occupancy probe |
| --- | --- | --- |
| absent | No replacement; NO SAVED SCENARIO. | Encode already succeeded; immediate save. |
| payload, empty/invalid JSON/unsupported version/noncanonical numbers/semantic errors | Decode/validation failure; old current remains. | Occupied; capture valid new encoding and request overwrite without interpreting old bytes. |
| payload exceeding codec cap or invalid UTF-8 | Codec TooLarge / Json(InvalidUtf8); old current remains. | Occupied **if the adapter actually returned payload**. This is possible with reviewed Zig scenario MemoryStore's arbitrary-byte slot. |
| native oversized_slot / native io.InvalidUtf8 / any raw failure | Store failure; no replacement. | Store failure; no overwrite modal and no save. |
| OutOfMemory | Propagate resource error; no fallback/default/replacement. | Propagate resource error; no save and no new modal. |

Zig scenario MemoryStore deliberately has neither scenario length nor UTF-8 restrictions; only its preferences record has a cap. NativeStore rejects both before returning payload. Both return independently allocated load bytes (`zig/src/classic_store.zig:219–241,499–518`). Preserve that distinction; an assertion that “arbitrary unreadable bytes trigger confirmation” would misdescribe NativeStore. FallbackStore and NativeStore only fall back on absent, and write primary (`zig/src/classic_store.zig:123–148,512–522`).

Use `scenario.decodeDraftDetailed`, not compact decode errors, for detached load: preserve detailed too_large / json(anyerror) / version / canonical_number(field,kind) / validation(report). Its success owns an arena and has passed wire/version/canonical parsing, **not semantic validation**; run validate/fromDraft before publication. Detailed failures have inline reports/static number labels; OOM remains an error. `decodeDetailed` already validates but returns only inline ScenarioV1, so draft ownership must then be rebuilt if that alternative is chosen (`zig/src/scenario.zig:13–35,497–507,627–669`). For save, first check parse errors and produce/retain the semantic report, then existing canonical encode; encode's compact Validation loses detail and folds admission failures. Returned encoded bytes belong to the supplied base allocator (`zig/src/scenario.zig:236–266,444–485`).

Native durability is the reviewed store's concern: write/sync a separate exclusive temporary, close, then atomic replacement; failures before replacement preserve old destination, and cleanup failure is secondary. Do not add direct file writes to the coordinator or claim directory-fsync or cross-process compare-and-swap guarantees (`zig/src/classic_store.zig:524–582`). A present legacy slot can cause overwrite confirmation, after which save writes a new primary and leaves legacy intact.

## Regeneration from invalid current rules is safe in this source

There is **no rule-dependent arithmetic bug in the current regeneration path**. Rust `Campaign::new(seed, _rules)` ignores rules, uses fixed anchor/jitter/modulo constants and wrapping SplitMix arithmetic. Zig generator likewise discards rules and uses explicit wrapping arithmetic (`src/game/model.rs:282–327,398–403`; `zig/src/generator.zig:23–35,45–77`). Hazard scheduling/division belongs to simulation, not this generator.

Regenerate preserves typed seed/rules and replaces only worlds (`src/scenario/mod.rs:60–71`). The UI enables every footer operation except invalid Apply; thus regenerate is intentionally reachable with semantic errors or invalid raw text (`src/editor/layout.rs:190–220`). Invalid numeric text retains its last typed value in 3C; regeneration uses that value and buffer reset discards invalid raw text. Invalid hazard period/caps/tick_hz can remain invalid afterward; generated worlds can also exceed an invalid lowered cap. That is an editable invalid draft, not authority corruption. **Do not prevalidate current rules to gate regeneration:** doing so narrows source and prevents a recovery operation. Validation remains required for save/apply.

Reviewed `ScenarioDraft.regenerateWorldsFromSeed` allocates a complete replacement before destroying old draft (`zig/src/scenario.zig:103–108`). 3D must extend this to the full editor epoch: generate candidate and all resulting 3C buffers before publication. Failure must preserve typed current, raw buffers/errors/preedit/focus and ORIGINAL. Do not mutate the live draft first and then encounter buffer-allocation OOM.

## Proposed smallest ownership and API seam

Compose a move-only `EditorSession` by value: one 3C editor, one modal/capture capsule, typed status, and stable base allocator. Modal kinds are exactly the seven in the scoped Task3C requirements. Overwrite owns encoded bytes independently of current/ORIGINAL arenas; apply owns an inline ScenarioV1; other kinds have no stale draft/slot pointer. Do not add duplicated focus/text/modal state, a saved RawStore context pointing into a movable owner, or a stored AppCore back-pointer.

A stateless TransactionCoordinator/module receives `*EditorSession`, borrowed `RawStore` and, only for outer application transitions, `*AppCore` per call. The concrete store and supplied context must outlive that call. Build raw adapters after a store moves; never retain `store.raw()` inside the same by-value store owner. Have pure request/confirm return explicit outcomes such as unchanged, confirmation_opened, draft_loaded, saved, close_requested or apply_requested(ScenarioV1), with typed recoverable failures and distinct OOM. Exact names are implementation choices; absent-load and modal-opened must not share an ambiguous bool at the integration boundary.

Stage load decode + validation + complete 3C current replacement before publishing; free raw outcome/temporary drafts on all exits. Revert clones ORIGINAL; factory constructs a new default; regenerate constructs worlds without validating current rules; each uses 3C's allocation-before-replacement seam. Saving does not use current arena for retained encoding. Transfer the owned save buffer into the modal only after encoding and successful occupied probe. Dismiss/deinit/displacing Cancel frees captures once. Keep source's direct Cancel exception while immediately disposing displaced captures; this removes Rust's transient unrelated pending values without changing its visible result.

**Proposed OOM policy:** Rust has no recoverable allocation contract here. Request-stage OOM opens no new modal and preserves resident editor/status/authority/slot. On a confirm attempt, take the capsule into a local owner at entry, as source takes the modal; any failed attempt, including OOM, consumes it, releases captured bytes and requires a new request. All content preparation remains transactional and preserves current/ORIGINAL/application/durable slot. This is explicitly distinct from a 3C standalone edit's requirement to preserve its modal on OOM: 3D has already consumed the confirmation before invoking replacement. Test that policy rather than silently choosing automatic retry. A retained typed status can be updated without allocation; formatted status text must not turn a successful durable save into an OOM failure afterward. Capture typed StoreFailure ownership before formatting/rendering; use static success/absent status text.

Open: construct the detached EditorSession from **active initial scenario**, finish allocations, then install session and set editing mode/clear clock. Already editing is inert. While editing, controller/gameplay operations are held. Close: release session, set playing/clear clock, clear recoverable status through an explicit AppCore seam; preserve simulation/active scenario/commands/selections/sequence/speed. Source close does not restart (`src/app/core.rs:821–831,833–901,959–964`; `tests/app.rs:67–91`). `setMode` already clears clock; Zig's `recover()` explicitly clears failure and clock, so a narrow close integration can compose those, without touching private simulation (`zig/src/classic_app.zig:210–226`).

Apply: confirm revalidates and compares full meaningful values, then call AppCore.replaceScenario before dropping session. Its current admission checks world identity/initial remainders/semantic values and fingerprint, rederives warnings, and prepares scenario + simulation + fixed clock before swapping. Failure keeps editing session and old authority; success drops editor and returns playing. Current admission/construction is allocation-free: do **not** invent application-install OOM. Exact errors are Validation, InvalidInitialState, StaleFingerprint (`zig/src/scenario.zig:35,269–285`; `zig/src/classic_app.zig:278–309`). Compare actual seed/rules/world values/name bytes/live warning entries/fingerprint; never use only a hash, raw struct memory/padding, draft pointers or arenas. Rust derives value equality, and ordinary guarded replacement dismisses a modal rather than reaching stale equality (`src/scenario/mod.rs:196–202`; `src/editor.rs:661–676`; `tests/scenario_editor.rs:328–360`).

Successful replacement resets selection/hover/touch, selected field Atmosphere, sequence/tick/commands/new simulation, visual time, normal resume speed, normal speed unless onboarding hold requires paused, help, failure and clock. Source additionally resets UI focus/camera and schedules Restart advisory; those owners are later tasks, with future observation after successful replacement rather than coordinator-owned implementations. Preferences persist (`src/app/core.rs:904–920,966–982`; `zig/src/classic_app.zig:278–309`). Ordinary restart uses active scenario, never whatever is currently saved.

## Minimal meaningful tests for implementation

1. **Real MemoryStore load:** clean absent/success; malformed/wrong version/noncanonical/semantic invalid preserve full current/ORIGINAL; dirty request performs zero reads and confirm sees a slot changed after request. No new primary during legacy load. Invalid text makes the otherwise value-equal editor dirty.
2. **Save order and capture:** InvalidText/semantic error produces zero store load/save calls; empty slot immediate save; present empty/invalid/oversized/arbitrary-byte memory payload asks confirmation without decoding it. Dismiss preserves slot/draft. Captured encoded bytes survive editor movement/current-epoch lifetime and are saved exactly; overwrite confirmation performs no second load/re-encode. Changed slot after request is overwritten only when confirmed.
3. **Real native store:** temporary fixture, absent/valid/invalid readable slot; 65,536-byte readable raw presence versus 65,537-byte raw failure; invalid UTF-8/io failure blocks both fallback and overwrite confirmation. Fresh adapter readback decodes exact saved candidate; injected before-persist/rename failure preserves primary/legacy bytes and removes temporary files. Do not mutate real profile roots.
4. **One-shot failures/cancel:** failed confirmed save/load leaves old content/slot, consumes modal/capture, reports exact typed error, second confirm NoConfirmation; new request retries. All seven modal kinds dismiss without content mutation. Direct Cancel's active-modal exception disposes old captures; clean close preserves application state. Deinit active captured save/apply without leaks/double free.
5. **Apply authority:** InvalidText then semantic rejection; warning-only candidate works; return captured value; test an intentionally unequal pending candidate with same fingerprint to exercise value comparison, plus missing capture and fresh revalidation error. A normal replace while modal instead dismisses and yields NoConfirmation. Admission rejection leaves editor/mode/active/simulation/commands/clock state unchanged; success resets required session values and ordinary restart uses newly active scenario. Existing Rust “stale” test is modal dismissal, not equality-mismatch coverage.
6. **Revert/default/regenerate recovery:** confirm source-specific current replacement while ORIGINAL stays fixed; preserve typed seed/rules on regenerate, use last typed values when raw seed/rule text is invalid, clear parse errors/canonicalize buffers, keep section/world/focus/preedit semantics. Exercise period zero and lowered caps to prove safe generation still leaves semantic errors, then reject apply/save. Dismiss is inert.
7. **OOM across real operations:** failing allocator at every load/decode/current-epoch construction/encoding/capture/store-message/native temporary path allocation; inspect full old content, arena/projection lifetimes, raw slot and zero premature writes. Request OOM keeps capsule/status; confirmed OOM consumes capsule under the explicit proposed policy. No allocation after successful persist can misreport failure. Wrong-record facade refuses before callbacks; repeated replace/regenerate/confirm/dismiss cycles release obsolete epochs and captures.
