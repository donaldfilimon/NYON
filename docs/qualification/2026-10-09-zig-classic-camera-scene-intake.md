## Required Rust parity

The actual Classic modules are `src/presentation/camera.rs`, `scene.rs`, `picking.rs`; Living/Workshop exports are separate (`src/presentation/mod.rs:3-14`). All vectors/matrices and visual quantities are f32. CameraMatrices holds view, projection, projection*view and its inverse; finiteness checks all 64 scalars (`camera.rs:20-49`, `225-242`). CameraState owns target/current and target yaw/pitch/distance, both matrix sets, logical viewport and motion (`camera.rs:52-65`). Defaults: target zero, yaw 0, pitch 55 degrees, distance 15; pitch 35..70 degrees, yaw -45..45, distance 8..24 (`camera.rs:10-18`, `68-89`). Do not silently substitute f64 angle conversion for Rust `f32.to_radians`.

Camera viewport independently replaces nonfinite components with 1 and clamps each finite component to >=1 (`camera.rs:200-213`). AppCore instead ignores a nonfinite viewport and accepts zero after clamping components >=0; picking uses that raw AppCore viewport, so zero still rejects even though camera matrices remain finite (`src/app/core.rs:349-355`, `390-397`). Eye is target plus `(sin(yaw)*cos(pitch)*distance, sin(pitch)*distance, cos(yaw)*cos(pitch)*distance)`. RH look-at uses Y-up; aspect clamps to 0.1..10; vertical FOV 45 degrees, near 0.1, far 100; projection multiplies view (`camera.rs:215-242`). The resolved dependency is glam 0.33.12, despite manifest range 0.33.6 (`Cargo.toml:28`, `Cargo.lock:1137-1142`). No OpenGL -1..1 depth or Vulkan Y flip belongs in Classic camera. Resolved DirectX wrapper calls `perspective<true,true,false>` (`.../src/camera/rh/proj.rs:203`). Actual math uses `f=normalize(center-eye)`, `s=normalize(cross(f,up))`, `u=cross(s,f)` with columns `(s.x,u.x,-f.x,0)`, `(s.y,u.y,-f.y,0)`, `(s.z,u.z,-f.z,0)`, `(-dot(eye,s),-dot(eye,u),dot(eye,f),1)` (`.../src/camera/camera_impl.rs:21-33,56-64`). Perspective uses sin_cos(0.5*fov), h=cos/sin, xx=h/aspect, yy=h, inverseRange=1/(far-near), zz=-far*inverseRange, tz=-near*far*inverseRange, zw=-1, assembled as column values `(xx,0,0,0)`, `(0,yy,0,0)`, `(0,0,zz,zw)`, `(0,0,tz,0)` (`.../src/camera/camera_impl.rs:134-169`). Inversion/SIMD multiply arithmetic and libm rounding remain explicit 3G0 review targets; this intake does not claim exact bit parity.

Full update uses duration seconds clamped 0..0.25 and blend `1-exp(-12*seconds)`; interpolates yaw, pitch and distance, then rebuilds both matrix sets. Reset changes target angles/distance, preserves target position, viewport and motion; full motion reset eases rather than immediately resetting current state (`camera.rs:96-197`).

## Proposed bounded interface and ownership

Existing AppCore CampaignView copies worlds/hazard and borrows fleet slice only until mutation/restart/deinit; synchronous scene extraction must finish first and retain no fleet pointers (`zig/src/classic_app.zig:76-89,133-136`). Existing projections expose activeScenario, clockAlpha, selection fields and visual_time; 3B accepts ID-only pick results with resident admission and returns observations (`zig/src/classic_app.zig:105-110,130-136,187-189`; `zig/src/classic_commands.zig:31-77`). Session.presentation returns transient override or durable preferences; Session reset/presentation effects are available (`zig/src/classic_session.zig:15,58-60,334-346`). Core advance currently keys visual time off durable motion, so transient override synchronization requires a reviewed composition change, not a second clock (`zig/src/classic_app.zig:229-237`). Current advisory feature Observation is borrowed only synchronously; no finished Snapshot API is assumed while 3F1 is active (`zig/src/classic_advisory_types.zig:10-17`).

Proposed sequential split:

1. **3G0 math interface review only.** Specify value Vec2/Vec3/Vec4 and column-array Mat4, matrix-vector/matrix-matrix multiplication, RH lookAt, DirectX perspective, inversion and tryNormalize/finite/total-order helpers. No dependency addition. Pin operation order and tolerance policy separately from exact integer/seed/value parity; review actual resolved glam implementations before implementation. Generic inversion error handling and external invalid camera mutation policy must be stated explicitly; current source computes inverse without a Result.
2. **3G1 pure camera/picking.** Own classic_math.zig (if approved), classic_camera.zig, classic_picking.zig and focused tests. Proposed `Camera.init/setViewport/setMotion/orbit/zoom/reset/update(delta_ns)`, `Ray.fromLogicalPointer(...) ?Ray`, `sphereDistance`, `pickAfterHud`. No raw event/DPR/GPU types. Port source fixtures plus full/reduced reset, zero/nonfinite viewport, invalid rays, positive-root cases and tie order. Math results checked against independent/Rust-captured witnesses in Debug/ReleaseSafe/ReleaseFast with recorded tolerance, never assumed bit identical across libm/SIMD.
3. **3G2 immutable scene.** Own classic_scene.zig and scene tests. Proposed `buildScene(CampaignView, scenario_fingerprint:u64, alpha:f32, SceneView, ?SceneAdvisory, time:f32, *const Camera, PresentationPreferences) SceneFrame`. Prefer caller-owned fixed value arrays [7]worlds/[512]fleets/[256]routes plus counts, avoiding campaign pointers and allocator failure. Bounded scratch selects first512 in stable ID order across ALL borrowed fleets before endpoint filtering, without changing campaign. Dedupe uses only encountered emitted keys; fixtures must prove caps/invalid endpoints/duplicate IDs/order and first-fleet curve. SceneAdvisory is only copied priority+score derived by reviewed3F owner, not fake scores.
4. **3G3 narrow composition after reviews.** Assign camera to Session or a presentation owner, avoid import cycles; consume reset_camera/presentation_changed immediately after successful transactions. One effective presentation preference source must drive camera, scene and existing visual clock. Create temporary CampaignView, synchronously copy frame, discard borrow before any tick/restart. Route picked ID through existing3B operations and3E observations; do not infer onboarding success from a frame. Parent owns shared exports/gate integration.

Add source-faithful literals and independent saturated fixtures; compare digest AND pending queue before/after camera/scene/preferences; test no mutation on rejected math/picking input. Fixed storage is Proposed, not a Rust API requirement. Real renderer globals/uniform ABI/layout, native/browser input, DPR/Retina rendered matrices, actual HUD opaque gaps, guide holds/host baseline, accessibility and visual acceptance remain Task6/3H/3I/3J. No host/manual proof is supplied here (`task-3-app-inventory.md:175-179,343-362,389-443`). Task3 remains Partial.
